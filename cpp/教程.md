# bardecode-cpp 实现教程：从图片到条码内容，一步一坑

本文带你从零走一遍这个 C++ 程序的完整流程：**读图 → YOLOv8 定位条码 → 裁剪 → zxing-cpp 解码 → 输出 JSON**。每一节对应 `src/` 里的一个模块，会贴出关键代码、解释用到的库函数、指出移植时踩过的坑，并给出官方文档链接。

如果你还没构建过，先看 [README.md](README.md)。下面假设你已经能跑：

```bash
./build/bin/Release/bardecode.exe tests/fixtures/ean13_photo.png
```

---

## 0. 全景：数据是怎么流动的

```
图片文件
  │  image_io.read_image()          —— OpenCV cv::imread
  ▼
cv::Mat (BGR, H×W×3)
  │  detector.detect()              —— letterbox → onnxruntime 推理 → NMS
  ▼
std::vector<Detection>              —— 每个条码的框（原图坐标）+ 置信度
  │  pipeline.process_image()       —— 逐框裁剪
  ▼
cv::Mat crop
  │  decoder.decode_region()        —— zxing-cpp ReadBarcodes
  ▼
std::vector<Decoded>                —— format + text + 四角坐标
  │  image_io.format_report_json()  —— nlohmann/json
  ▼
JSON 文本（stdout）
```

三个主角库全是原生 C/C++ 库（Python 版只是它们的胶水层）：

| 库 | 作用 | 官方文档 |
|---|---|---|
| OpenCV | 读图、缩放、NMS | https://docs.opencv.org/4.10.0/ |
| onnxruntime | 跑 YOLOv8 ONNX 模型 | https://onnxruntime.ai/docs/api/cxx/ |
| zxing-cpp | 解码条码/二维码 | https://zxing-cpp.github.io/zxing-cpp/ |
| nlohmann/json | 拼 JSON | https://json.nlohmann.me/ |

## 1. 读图：OpenCV 的 cv::imread

对应 `src/image_io.hpp` —— 整个程序最简单的一步：

```cpp
inline cv::Mat read_image(const std::string &path) {
    cv::Mat img = cv::imread(path, cv::IMREAD_COLOR);
    if (img.empty()) {
        throw std::runtime_error("file not found");
    }
    return img;
}
```

要点：

- **`cv::Mat`** 是 OpenCV 的图像/矩阵类。内存布局默认是 **HWC 交错**（高×宽×通道，一个像素的 B、G、R 三个字节挨在一起），行与行之间可能有 padding（`step`）。这与后面 ONNX 需要的 **NCHW** 布局不同，是移植时的核心转换点，见 §3.3。
- `IMREAD_COLOR` 强制转成 3 通道 BGR（注意 OpenCV 是 **BGR** 顺序，不是 RGB）。
- 打不开文件时 `imread` **不抛异常、不返回错误码**，只是返回空 Mat，所以必须用 `img.empty()` 判断。Python 版里 `cv2.imread` 返回 None 再用 Pillow 兜底；C++ 里 OpenCV 的 imgcodecs 模块自带 webp/png/jpeg 编解码器（我们源码编译时包含了 3rdparty 的 libjpeg-turbo/libwebp），所以不需要 Pillow 等价物。

踩坑提示：读文件失败时 OpenCV 会往 stderr 打一条 `cv::findDecoder ... can't open/read file` 警告，属正常现象。

参考：
- imread/imwrite 教程：https://docs.opencv.org/4.10.0/d4/da8/group__imgcodecs.html
- cv::Mat 入门：https://docs.opencv.org/4.10.0/d6/d6d/tutorial_mat_the_basic_image_container.html

## 2. 检测（一）：letterbox —— 把任意尺寸的图装进 640×640

对应 `src/detector.cpp` 的 `BarcodeDetector::letterbox()`。

YOLOv8 是固定输入尺寸（640×640）的模型，但照片什么尺寸都有。直接 `resize` 到正方形会把条码拉变形、降低检测精度。标准做法是 **letterbox**：保持长宽比缩放，短边方向用灰色 (114,114,114) 填充。

```cpp
double scale = double(target) / std::max(h, w);        // 缩放系数
int new_w = std::max(int(std::round(w * scale)), 1);
int new_h = std::max(int(std::round(h * scale)), 1);

cv::resize(img, resized, {new_w, new_h}, 0, 0, cv::INTER_LINEAR);

lb.pad_w = (target - new_w) / 2;                       // 左边留白
lb.pad_h = (target - new_h) / 2;                       // 上边留白

lb.out = cv::Mat(target, target, img.type(), cv::Scalar(114, 114, 114));
resized.copyTo(lb.out(cv::Rect(lb.pad_w, lb.pad_h, new_w, new_h)));  // ROI 拷贝
lb.ratio = 1.0 / scale;                                // 记住还原系数
```

用到的 API：

- **`cv::resize(src, dst, Size, 0, 0, interpolation)`**：缩放。缩小用 `INTER_LINEAR`（默认、够用）。
- **`cv::Mat(rows, cols, type, Scalar)`**：新建一张全部填成灰 114 的画布。
- **ROI（感兴趣区域）**：`mat(cv::Rect(x, y, w, h))` 返回子矩阵视图，`copyTo` 把缩放后的图贴到画布中央。这是 OpenCV 的惯用法，零拷贝的视图 + 显式拷贝。

**为什么要记住 `ratio` 和 `pad`**：模型输出的是 640×640 坐标系里的框，最后要还原回原图坐标：

```
原图坐标 = (640坐标系坐标 - pad) × ratio
```

这行公式在 `detect()` 末尾 + `std::clamp` 防越界。

参考：
- resize：https://docs.opencv.org/4.10.0/da/d54/group__imgproc__transform.html
- Ultralytics 官方 letterbox 实现（本项目的 Python 原型就是仿它写的）：https://github.com/ultralytics/ultralytics/blob/main/ultralytics/data/augment.py 中的 `LetterBox`

## 3. 检测（二）：onnxruntime 推理 —— 程序的核心

对应 `src/detector.cpp` 的构造函数和 `detect()`。分四步：建会话 → 预处理 → 跑模型 → 后处理。

### 3.1 创建推理会话

```cpp
// 构造函数里，一次性完成
env_ = Ort::Env(ORT_LOGGING_LEVEL_WARNING, "bardecode");   // ① 全局环境
Ort::SessionOptions options;                                // ② 会话选项
options.SetGraphOptimizationLevel(GraphOptimizationLevel::ORT_ENABLE_ALL);
std::wstring wpath = std::filesystem::path(path).wstring(); // ③ 宽字符路径！
session_ = std::make_unique<Ort::Session>(env_, wpath.c_str(), options);

input_name_  = session_->GetInputNameAllocated(0, ...).get();  // ④ 查输入输出名
for (size_t i = 0; i < session_->GetOutputCount(); ++i) {
    output_names_.push_back(session_->GetOutputNameAllocated(i, ...).get());
}
```

onnxruntime C++ API 的对象模型（[官方文档](https://onnxruntime.ai/docs/api/cxx/README.html)）：

- **`Ort::Env`**：运行环境，管理线程池和日志。进程里建一个就够，所有 Session 共享。
- **`Ort::SessionOptions`**：线程数、优化级别、provider（GPU）等。我们纯 CPU，默认即可。
- **`Ort::Session`**：加载并持有模型。一个 Session 可多线程复用，所以 pipeline 里做成懒加载单例（`pipeline.cpp` 的 `static BarcodeDetector`，对应 Python 的模块级缓存）。

**坑 1（Windows 特有）**：Windows 上 `Ort::Session` 构造函数只接受 `const wchar_t*` 路径（Linux 是 `const char*`），所以要 `std::filesystem::path(path).wstring()`。报错是晦涩的"没有重载函数可以转换所有参数类型"。

#### 理解 ④：为什么要"查输入输出名"

一个 ONNX 模型本质上是一个计算图，像一个函数，但它的参数**不是按位置传的，而是按名字传的**。以 YOLOv8 为例，模型内部定义大致相当于：

```
函数 images(input: float[1,3,640,640]) -> output0(float[1,5,8400])
```

- 输入口的名字（`"images"`）是模型作者导出时起的，输出口叫 `"output0"`
- 调用 `Run()` 时签名是"给一组**名字** + 一组**张量**，按名字配对"——你拿着图片数据，但模型不知道该塞进哪个口，必须告诉它张量对应哪个名字。这和 Python 的关键字参数一个道理：`session.run(None, {"images": blob})`

| 调用 | 作用 | 本项目模型返回 |
|---|---|---|
| `GetInputNameAllocated(0, ...)` | 第 0 个（通常也是唯一）输入口的名字 | `"images"` |
| `GetOutputCount()` | 输出口有几个 | `1` |
| `GetOutputNameAllocated(i, ...)` | 第 i 个输出口的名字 | `"output0"` |

两个常见疑问：

- **为什么不硬编码 `"images"`/`"output0"`？** 这些名字不受标准保证，换一个导出工具或模型作者，可能变成 `"input.1"`、`"onnx::Reshape_453"` 之类。惯例是启动时向模型查询一次，存成成员变量（`input_name_`、`output_names_`），之后每帧推理直接复用。
- **`.get()` 在干什么？** `GetInputNameAllocated` 返回一个 RAII 智能指针（`AllocatedStringPtr`），指针销毁时字符串就没了。`.get()` 取出内容**拷贝进普通 `std::string` 成员**长期持有——即使临时智能指针离开作用域，名字还在。这是 C++ 里"句柄转值"的惯用法。

传错名字或传空（C++ 里不传输出名）会得到 "Invalid input name" / "At least one output should be requested" 这类报错——后者就是本项目实际踩到并修掉的 bug（见 §3.3 坑 3）。

### 3.2 预处理：BGR→RGB、除以 255、HWC→NCHW

模型期望的输入是 `float32[1, 3, 640, 640]`，取值 0~1，**RGB** 顺序。而 `cv::Mat` 是 uint8、BGR、HWC：

```cpp
cv::cvtColor(lb.out, rgb, cv::COLOR_BGR2RGB);   // 通道顺序
rgb.convertTo(blob, CV_32F, 1.0 / 255.0);       // 归一化到 [0,1]

// HWC -> NCHW：手工搬运（也可以用 cv::dnn::blobFromImage 一行搞定）
for (int y = 0; y < img_size_; ++y) {
    const float *row = blob.ptr<float>(y);      // 行指针：HWC，每像素 3 个 float
    for (int x = 0; x < img_size_; ++x) {
        for (int ch = 0; ch < 3; ++ch) {
            nchw[((size_t)ch * img_size_ + y) * img_size_ + x] = row[x * 3 + ch];
        }
    }
}
```

HWC→NCHW 就是把 `[H][W][C]` 重排成 `[C][H][W]`：通道 ch、第 y 行第 x 列的像素，源地址是 `row[x*3 + ch]`，目标地址是 `nchw[ch][y][x]`。理解了这一段，任何视觉模型的预处理你都会写了。

（偷懒写法：`cv::dnn::blobFromImage(image, blob, 1/255.0, Size(), Scalar(), /*swapRB=*/true)` 一个函数等价上面全部，OpenCV 文档：https://docs.opencv.org/4.10.0/d6/d0f/group__dnn.html#ga0b7b7c3c5305c3352bfa50152f7ab5a4 ）

### 3.3 构造张量并运行

```cpp
Ort::MemoryInfo mem = Ort::MemoryInfo::CreateCpu(OrtArenaAllocator, OrtMemTypeDefault);
std::vector<int64_t> shape{1, 3, img_size_, img_size_};
Ort::Value input = Ort::Value::CreateTensor<float>(
    mem, nchw.data(), nchw.size(), shape.data(), shape.size());

const char *input_names[] = {input_name_.c_str()};
auto outputs = session_->Run(Ort::RunOptions{nullptr}, input_names, &input, 1,
                             out_names.data(), out_names.size());
```

- **`Ort::Value`** 是张量。`CreateTensor<float>` 可以**包装已有内存**（零拷贝，推荐），也可以让它自己分配。`MemoryInfo` 指明数据在 CPU 上。
- **`Session::Run(...)`** 是推理本体。C++ 版必须同时给输入名数组和输出名数组。

**坑 3（与 Python 差异最大的一处）**：Python 里 `session.run(None, ...)` 传 None 表示"取全部输出"；C++ 版没有这个捷径，输出名传空会直接抛异常 **"At least one output should be requested."**——这是我们实际踩到并修掉的 bug，见 `detector.cpp` 构造函数里预取 `output_names_` 的循环。

### 3.4 后处理：置信度过滤 + NMS

YOLOv8 的原始输出形状是 `[1, 4+nc, N]`（nc=类别数，本项目模型 nc=1；N=8400 个候选框）。行优先展开成一维后：

- 第 0~3 行：框中心 cx、cy 和宽高 w、h（**640 坐标系，cxcywh 格式**）
- 第 4 行起：每个类别的分数

```cpp
// 1) 逐候选框取"跨类别最大分数"，做置信度过滤
for (int c = 0; c < cols; ++c) {
    float score = -1.f;
    for (int r = 4; r < rows; ++r) score = std::max(score, raw[r * cols + c]);
    if (score < conf_thres) continue;
    ...
}

// 2) cxcywh -> xyxy（左上角/右下角）
// 3) NMS 去重叠
std::vector<int> idx;
cv::dnn::NMSBoxes(boxes, scores, conf_thres, iou_thres, idx);
```

**`cv::dnn::NMSBoxes(bboxes, scores, score_threshold, nms_threshold, indices)`**（[文档](https://docs.opencv.org/4.10.0/d6/d0f/group__dnn.html#ga9d09d70f5b37aeb380710b313f3d8c11)）：非极大值抑制——同一个条码会被多个候选框命中，NMS 按 IoU（交并比）保留分数最高的、去掉与它重叠超过阈值（默认 0.45）的其余框。

**坑 4**：`NMSBoxes` 要的框格式是 `[x, y, w, h]` 且 (x,y) 是**左上角**。模型输出的是中心点格式，直接传进去 IoU 会算错（这就是代码里先转 xyxy 再拼 xywh_tl 的原因，Python 版还专门写了注释）。

最后把 640 坐标系的框按 §2 的公式映射回原图，`std::clamp` 到图像边界内，过滤掉零面积的框。

参考：
- onnxruntime C++ API：https://onnxruntime.ai/docs/api/cxx/README.html
- YOLOv8 输出格式详解（搜 "yolov8 onnx output 8400"）：https://docs.ultralytics.com/tasks/detect/
- NMS 原理图解：https://learnopencv.com/non-maximum-suppression-theory-and-implementation-in-pytorch/

## 4. 裁剪与调度：pipeline

对应 `src/pipeline.cpp` 的 `process_image()`。这一步没有第三方 API，纯业务逻辑，但结构值得学：

```cpp
for (const auto &d : detections) {
    // ROI 裁剪：又一个 cv::Rect 视图，注意用 (x1, y1, 宽, 高) 不是 (x1, y1, x2, y2)
    cv::Mat crop = img(cv::Rect(d.x1, d.y1, d.x2 - d.x1, d.y2 - d.y1));
    auto results = decode_region(crop, formats);       // 见 §5
    if (!results.empty()) { /* 收进 barcodes */ }
    else { /* 记进 undecoded：检测到了但解不出来 */ }
}

// 兜底：一个都没解出来时，对整图直接解码一次
if (fallback && ir.barcodes.empty()) { ... }
```

三个细节：

1. **`cv::Rect` 是 (x, y, width, height)**，不是 (x1, y1, x2, y2)。Detection 里存的是 x2y2，裁剪时要相减。这是 OpenCV 新手第一大坑。
2. **兜底逻辑**：检测模型可能漏检（比如条码太小、被遮挡），此时对整图跑一遍 zxing 兜底；解码结果自带的四角坐标算出 bbox（`detection_score = 0.0` 表示不是 YOLO 找到的），并按 IoU ≤ 0.5 清掉与之重叠的 undecoded 记录。
3. **去重**：同一个码可能被解出多次，按 `(format, text, bbox)` 三元组用 `std::set` 去重——C++ 里就是 `seen.insert(key).second` 惯用法。

## 5. 解码：zxing-cpp 原生 API

对应 `src/decoder.cpp`。zxing-cpp 本体就是 C++ 库（Python 包只是绑定），所以这段几乎是"翻译"：

```cpp
#include <BarcodeFormat.h>
#include <ReadBarcode.h>

// zxing 吃亮度图（不是彩色图），先转灰度
cv::cvtColor(image, gray, cv::COLOR_BGR2GRAY);

zxing::ImageView view(gray.data, gray.cols, gray.rows,
                      zxing::ImageFormat::Lum, static_cast<int>(gray.step));
auto results = zxing::ReadBarcodes(view, options);

for (const auto &r : results) {
    d.format = zxing::ToString(r.format());   // 如 "EAN-13"
    d.text   = r.text();                      // 解码内容
    // r.position() 给出四角点，用于兜底路径算 bbox
}
```

API 说明（[官方文档](https://zxing-cpp.github.io/zxing-cpp/group__api.html)）：

- **`zxing::ImageView`**：轻量图像视图，只存指针不拷贝数据。`ImageFormat::Lum` 表示单通道亮度。**注意传 `gray.step`**（一行实际占的字节数），有 padding 的 Mat 不传 step 会读歪。
- **`zxing::ReadBarcodes(view, options)`**：对图里所有可见条码解码，返回 `std::vector<Result>`。支持 EAN-13/UPC-A/Code128/QR/DataMatrix/PDF417 等几十种格式。
- **`ReaderOptions::setFormats()`**：格式白名单，只找指定格式更快更准。CLI 的 `--formats EAN13,QRCode` 最终落到这里。
- **`zxing::BarcodeFormatsFromString("EAN13|QRCode")`**：字符串转格式集合，竖线分隔；不认识的字符串抛 `std::invalid_argument`，正好对应 Python 版的 ValueError。

**坑 5**：2.2 版的头文件包含是 `#include <ReadBarcode.h>`（没有 `ZXing/` 前缀，2.3+ 才改）；C++ 侧格式名是 `"EAN-13"` 而 Python 绑定给的是 `"EAN13"`，做跨语言对拍时注意。

**坑 6**：`ZXing` 库的 CMake 目标名是 `ZXing`（不是 `zxing`），链接写错会变成裸 `-lzxing` 然后链接失败。

## 6. 输出：nlohmann/json

对应 `src/image_io.cpp`。nlohmann/json 是最接近 Python `json.dumps` 体验的 C++ 库——像写字面量一样构造 JSON：

```cpp
using json = nlohmann::json;
json j;
j["tool"] = report.tool;
j["results"] = json::array();
for (const auto &ir : report.results) {
    j["results"].push_back({
        {"image", ir.image},
        {"width", ir.width},
        {"barcodes", ...},
        {"error", ir.error ? json(*ir.error) : json(nullptr)},  // Optional -> null
    });
}
return j.dump(2);   // 缩进 2，等价 json.dumps(..., indent=2)
```

要点：`json(*ir.error) : json(nullptr)` 处理 `std::optional`（有值输出字符串，没值输出 `null`）；`dump(2)` 默认不转义非 ASCII（等价 `ensure_ascii=False`）。

参考：https://json.nlohmann.me/api/basic_json/dump/

## 7. 串起来：CLI 与退出码

`src/main.cpp` 手写了一个 30 行的参数解析器（Python 的 argparse 没有标准 C++ 等价物；真实项目可用 [CLI11](https://github.com/CLIUtils/CLI11) 或 [cxxopts](https://github.com/jarro2783/cxxopts)）。

流程：解析参数 → 建一次 `BarcodeDetector`（模型只加载一次，循环里复用）→ 逐图 `process_image` → 汇总成 `Report` → JSON 或 `--quiet` 纯文本输出。退出码与 Python 版一致：**0 成功 / 1 处理错误 / 2 文件不存在**。

一个 C++ 特有的结构差异：Python 版把"找不到文件"等错误都收进 `ImageResult.error` 字段继续跑下一张图；C++ 版照搬了这一设计（异常只作为传输手段，`catch` 后转成错误字符串），这样单张图失败不会中断整批。

## 8. 测试怎么写

`tests/` 用 GoogleTest，结构与 Python 的 pytest 一一对应：

```cpp
TEST(Postprocess, NmsSuppressesOverlap) {          // TEST(套件, 用例)
    std::vector<float> raw{100, 101, 100, 101, 50, 50, 50, 50, 0.9, 0.8};
    auto dets = BarcodeDetector::postprocess(raw, 5, 2, 0.25, 0.45);
    EXPECT_EQ(dets.size(), 1u);                    // EXPECT 失败继续，ASSERT 失败即停
}
```

经验：
- **纯函数最好测**：`letterbox`、`postprocess` 设计成静态纯函数，手工构造张量就能测，不用碰模型文件。
- **端到端测试需要固定输入**：`make_fixtures.py` 用 python-barcode + OpenCV 生成确定性的 EAN-13 图片（固定随机种子），C++ 测试只管读文件。
- **浮点别用 `EXPECT_EQ`**：`0.9f != 0.9`（float vs double），用 `EXPECT_FLOAT_EQ`——这是我们真实翻过的车。
- CMake 侧：`add_test(NAME x COMMAND x)` + `ctest --test-dir build -C Release`，测试通过 `bardecode_lib` 静态库链接被测代码（不是重复编译源文件）。

## 9. 构建系统速览

顶层 `CMakeLists.txt` 全部用 FetchContent 拉依赖，值得注意的几个决定：

- **OpenCV 裁剪编译**：`BUILD_LIST=core,imgproc,imgcodecs,dnn` 只编 4 个模块，省大量时间。
- **`BUILD_WITH_STATIC_CRT=OFF`**：OpenCV 在 Windows 默认用静态 CRT(/MT)，与我们 /MD 编译的代码混链报 LNK2038，必须关掉。
- **onnxruntime 不从源码编**：直接下载 nuget 官方预编译包（zip 格式），用 `IMPORTED` 目标包装头文件目录 + `.lib`，再 post-build 拷贝 DLL 到可执行文件旁。
- **`/utf-8` 编译选项**：zxing 源码里有 UTF-8 字符字面量，MSVC 默认 GBK 代码页会报 C3688。
- **模型分发的两个方向**：构建期 `copy_if_different` 把 43MB 的 ONNX 拷到 exe 旁的 `models/`；运行期 `default_model_path()` 按可执行文件目录找（`BARDECODE_MODEL` 环境变量可覆盖）——这是 C++ 里 `importlib.resources` 的土替代。

FetchContent 参考：https://cmake.org/cmake/help/latest/module/FetchContent.html

## 10. 动手练习建议

按顺序做，每一步都能独立验证：

1. **改 letterbox 填充色**（114 → 白色 255），跑 `test_detector`，看哪个断言红了——练测试驱动。
2. **用 `cv::dnn::blobFromImage` 替换手工 NCHW 循环**，对拍 `ean13_photo.png` 的输出应该逐字节一致。
3. **加 `--save-crops` 参数**：把每个检测框裁剪图写到磁盘（`cv::imwrite`），直观看看模型找到了什么。
4. **打印 NMS 前后的候选框数量**，体会 8400 个候选是怎么缩到几个的。
5. **换模型**：从 HuggingFace 找另一个 YOLOv8 条码检测 ONNX，`--model` 传入试试（注意输出格式 `[1, 4+nc, N]` 要一致）。

## 附：本项目踩坑速查表

| 症状 | 原因 | 修法 |
|---|---|---|
| Session 构造"无匹配重载" | Windows 要求宽字符路径 | `std::filesystem::path(p).wstring()` |
| Run 抛 "At least one output should be requested" | C++ API 不接受空输出列表 | 预取 `GetOutputNameAllocated` 传入 |
| C2589 `"(":"::"` 非法标记 | windows.h 的 min/max 宏污染 | `#define NOMINMAX` |
| C3688 无效文本后缀 | MSVC 按 GBK 读 UTF-8 源码 | CMake 加 `/utf-8` |
| LNK2038 RuntimeLibrary 不匹配 | OpenCV 静态 CRT vs /MD | `BUILD_WITH_STATIC_CRT=OFF` |
| LNK1181 找不到 zxing.lib | CMake 目标名大小写 | 链接 `ZXing` |
| 找不到 opencv_modules.hpp | OpenCV 生成头在顶层 build 目录 | include `${CMAKE_BINARY_DIR}` |
| 裁剪区域报错 | `cv::Rect` 要宽高不是右下角 | `Rect(x1, y1, x2-x1, y2-y1)` |
